## 1. ゲームの基本設計（維持事項）

1. **福岡県60市町村**から2自治体を選んでドラフト。任意の市町村の検索・指名が可能。敵側も2自治体で、ドラフト開始時から公開。
2. **前衛1＋後衛1**の2対2。前衛が攻撃を受け、前衛が倒れた場合に生存する後衛が前へ移動する。
3. **独立ATB・完全オート**。行動は通常攻撃と各自治体の固有必殺技1つのみ。
4. **左右対面の2.5D疑似遠近感**。奥側の後衛は上・小さく、手前側の前衛は下・大きく描画。
5. 使用できる実統計は現行CSVの人口、高齢者割合、面積、概算人口密度。**能力への変換・輪郭・技効果はゲーム用設定**であり、産業・森林・鉄道の未取得データを実測値として扱わない。
6. 同一シード、同一編成・配置、同一データ・バージョンから得られる**戦闘ログ・勝敗は同一**。演出や端末FPSは結果に影響しない。

### 1.1 固定戦闘パラメータ（調整対象）

| 要素 | 仕様 |

| ゲーム内上限 | 50ゲーム秒＝3000固定tick |

## 2. 状態モデル：計算・演出・UIを分離

### 2.1 唯一の正となる戦闘状態

- **生存判定は `hp > 0`** に一本化する。Ver.0.4.1の`dead`を廃止し、`isAlive(unit)`で参照する。`koTick`は演出履歴であり、生死判定に使用しない。
- `initialSlot`は編成時の列（front/rear）として**変更しない**。`effectiveRole(unit, state)`は生存前衛がいなければ生存後衛をfrontとして返す。戦闘中の行動種別は現在の役割と技の種類で決め、`initialSlot`のみで判定しない。
- 表示用の移動座標・KO位置は戦闘ルールの状態に含めず、**イベントにその時点の座標を記録**する。
- 勝敗確定後は計算が進まない。演出キューの再生中でも内部`battle.tick`は固定し、**演出時計 `presentationElapsedMs`**のみ進む。

### 2.2 状態型（概念例）

```ts
type Side = 'blue' | 'red';
type Role = 'front' | 'rear';
type AttackStyle = 'melee' | 'ranged' | 'magic' | 'support';
type EffectKind = 'damage' | 'heal' | 'shield';
type DisplayKind = EffectKind | 'ko' | 'promotion' | 'victory';
type BattlePhase = 'RUNNING' | 'RESOLVING' | 'PRESENTING_FINAL' | 'RESULT';

type UnitState = {
  id: string;
  side: Side;
  initialSlot: Role;
  hp: number;
  maxHp: number;
  atb: number;
  sp: number;
  shield: { amount: number; expiresAtTick: number } | null;
  koTick: number | null;
  promotedAtTick: number | null;
  // 与ダメージ、回復などの記録
};

type PositionSnapshot = { x: number; y: number; scale: number };
type DisplayEvent = {
  eventId: number;             // tick内の順番まで含む一意の連番
  tick: number;
  type: DisplayKind;
  actorId?: string;
  targetId?: string;
  skillId?: string;            // 技名ではなく安定した識別子
  attackStyle?: AttackStyle;
  actorPosition?: PositionSnapshot;
  targetPosition?: PositionSnapshot;
  koPosition?: PositionSnapshot;
  amount?: number;             // 算出済みの生値。0も有効
  hpBefore?: number;
  hpAfter?: number;
  shieldAbsorbed?: number;
  label: string;               // 表示用。ルール分岐に使わない
};
```

**設計上の要点：** イベントの描画で`actor.hp > 0`や`target.hp > 0`を再判定しない。同時相打ちや致死攻撃であっても、**行動が成立した時点のスナップショット**を使い、当該一撃と数値を最後まで表示する。KO状態の新たな攻撃は発行されない。

### 2.3 論理配置・描画座標

現行Ver.0.4.1に合わせた1000×560座標系で次を初期値とする。

| 陣営 | 前衛（手前） | 後衛（奥） |
|---|---|---|
| 味方 | `(335,430,1.15)` | `(155,257,0.79)` |
| 敵 | `(665,430,1.15)` | `(845,257,0.79)` |

- 生存前衛がいない場合、**生存する元後衛のみ**前衛位置へ移る（座標遷移は約0.35〜0.55秒）。倒れた元前衛は画面から消える。
- KO発生時の`koPosition`は**倒れる直前に描画されていた座標**を保存する。通常は`effectivePos(u)`で得られる。既に昇格済みの後衛がKOした場合は前衛位置。
- **前衛と後衛が同じtickにKOした場合**、後衛を繰り上げてから座標計算してはいけない。後衛は元の後衛位置でKOしたものとして位置を固定する。必要なら移動中の補間済み座標を保存する。
- 技演出の始点・終点もイベント生成時に凍結し、その後の昇格・KOで移動しない。
- 位置計算に配列上の`indexOf`や`slot===0`を多用せず、`side`と`effectiveRole`を入口にする。元スロットは「どちらが昇格できるか」を決める属性として残す。

## 3. 固定tick処理順と同時KO（F04）

### 3.1 1tickの正式な処理順

1. **開始スナップショット**：全キャラのHP・シールド・生存・有効前衛・画面上の論理配置を記録。
2. **期限切れシールド除去**：`expiresAtTick <= currentTick`なら効果なしとし、必要な表示イベントを追加。
3. **ATB更新・行動決定**：tick開始時に生存するユニットだけが行動候補になる。同一tickでの行動可否は処理順に左右されない。
4. **対象・効果量の決定**：開始スナップショットを基準に選択する。`skillId`と`attackStyle`をイベントに格納し、表示時には技名の文字列で分類しない。
5. **効果の一括適用**：同じtickのダメージ／回復／シールドを受け手別に集約して一回で適用。表示イベントごとの算出値は失わず保持。
6. **KOを一括確定**：開始時に生存し、適用後`hp <= 0`となった全ユニットを列挙。全員のKO位置を**昇格前の状態**から固定する。
7. **昇格判定**：各チームについて「**元前衛がKOし、元後衛が生存**」の場合のみ後衛昇格イベントを発行する。元後衛もKOした場合は発行しない。
8. **終了判定**：全滅・時間切れの決着を計算して一度だけ固定する。結果画面にはまだ遷移しない。
9. **イベントの公開**：表示キューへイベントを**一件ずつ・一意ID付き**で追加。再生側は取りこぼしなく処理。

### 3.2 同時適用の計算規則

- tick開始時の生存ユニットによる行動は、そのtick中に相打ちでKOになっても**成立**する。
- ダメージと回復が同時に来た場合、開始HPに対して**シールド吸収後のダメージと回復を合算し、最終的に0〜最大HPへclamp**する。途中の一時的なHP0をKOとみなさない。
- シールドはそのtick開始時の残量で吸収し、新たに張られたシールドは**次tickから有効**。同時発動者やチームの配列順で有利不利が出ないようにする。
- 全員の効果適用が終わるまで昇格・KOイベントを確定しない。
- イベント再生順は**行動（確定済み安定順）→ダメージ等のヒット→KO→昇格→決着**。同時行動の物理的な決着は同時であり、演出の順序でHPを再計算しない。

## 4. イベントキューと決着演出（F02・F06）

### 4.1 `events.at(-1)`を廃止する

- シミュレーションは発生イベントを`eventId`連番付きのログへ追記する。
- 描画側は独立した`presentationQueue`、`activeEvent`、`presentationElapsedMs`を持ち、**前から順番に消費**する。
- **同じtickのイベントを省略・統合してはならない。** 例：青前衛の攻撃、赤後衛の攻撃、赤前衛のKO、赤後衛の昇格はすべて表示する。
- 基本演出時間の目安：通常攻撃0.35〜0.55秒、必殺技1.0〜1.6秒、KO0.35〜0.6秒、昇格0.35〜0.55秒。1件のイベントにつき最低1描画フレームを保証する。
- ダメージ数字の表示条件は**イベントの種別・受け手ID・計算済み数値**で決め、受け手がKOしたかどうかで隠さない。致死攻撃や相打ち時も描画。
- 通常時にイベント間の長い待機時間が発生する場合は、その間の戦闘計算を進めてよい。ただし、**未表示イベント数が閾値を超える場合はシミュレーションを停止しキューを先に再生**する。上限は暫定8件（ログは別途無制限または十分な上限）。
- 必殺技などの主要イベント再生中は計算を一時停止するか、シミュレーションを先行させても**イベント表示用の状態スナップショット**を持つ。初期実装では前者を優先し、状態の先読み表示を防ぐ。

### 4.2 終局状態機械

```text
RUNNING
   │  このtickで勝敗確定
   ▼
RESOLVING            ← 勝敗・戦闘tick・最終状態を固定。新規戦闘行動は発生しない。
   │  未表示のイベントを順番に描画
   ▼
PRESENTING_FINAL     ← 決着の一撃／KOを見せ終えた後、最低1,000msの余韻
   │  最低時間が経過
   ▼
RESULT               ← 結果画面へ一度だけ遷移
```

- 最終一撃を描画する前に`finish()`を呼ばない。`battle.done`は**計算終了**であり、即画面遷移を意味しない。
- 1秒の余韻は**最後の関連イベントの演出完了後**から数える。演出が1.2秒なら「1.2秒＋1秒」が原則で、単に勝敗確定から1秒待つだけにしない。
- 画面には最終HPと「勝負あり」または「決着！」の表示を残す。
- 一時停止中は演出時計も止める。再開後に続行する。
- 「結果まで進む」は**ユーザーによる明示的なスキップ操作**なので、演出を省略して即結果へ遷移してよい。ただし計算は最後まで完了させる。
- 決着時の最後の通常攻撃・必殺技、KO、昇格、勝敗のログは、スキップ有無にかかわらず保持する。

### 4.3 画面更新の規則

- Canvasは`requestAnimationFrame`で必要な描画を続ける。演出時計はブラウザの実時間で進め、再生速度の影響をどこまで与えるかは**戦闘tickのみ速度変更、演出の視認性は実時間の最低表示時間を維持**を既定とする。
- HUDの生存・前衛後衛・HP数値は、各戦闘イベントを反映したタイミングで更新。イベントキュー再生中に未来の最終HPだけが先に表示されないよう、**表示用スナップショット**から算出する。
- プレイヤーが一時停止を押した瞬間、計算時計・演出時計の両方を止める。
- 背景／演出を止めてタブから戻ったとき、経過壁時計で一気に処理を飛ばさず、`delta`をクランプする。

## 5. シールドの上限・期限（F05）

Ver.0.4.1の`u.shield += 23`は廃止し、**期限付き・非加算式**に変更する。

| 項目 | 暫定仕様 |
|---|---|
| 対象 | 使用時に選ばれた味方の有効前衛 |
| 基本付与量 | 23ダメージ分 |
| 上限 | `min(35, round(maxHp × 0.30))` |
| 効果期限 | 付与から**8ゲーム秒＝480tick** |
| 再付与 | **加算しない**。残シールドと新規付与量の`max`（上限内）へ更新。期限は再付与時から延長 |
| 期限切れ | 残量に関係なく0とする |
| 対象KO | 対象が戦闘不能ならシールド消滅。別ユニットへ自動移譲しない |
| AIの発動条件 | 対象シールドの残量が**新規付与量の半分未満**、または期限切れのときのみ必殺技を使う。条件未達ならSP保持・通常攻撃 |

**表示**：対象キャラの周囲に青い輪を表示。HUDには例「盾 18（残4.2秒）」と表示できるが、狭い画面ではアイコンだけでもよい。残量0になった時点で輪は消える。

**調整指標**：防御型が50秒の間に永久バリアにならないこと／前衛を維持する価値があること／防御型の勝率が極端に偏らないことを複数の編成とseedで確認する。

## 6. 攻撃種別・魔力・KO・昇格（F01・F07・F10）

### 6.1 技を文字列ではなくIDと種別で識別

```ts
type SkillDefinition = {
  id: 'elder_magic' | 'density_rush' | 'wide_guard' | 'generation_wisdom' | 'town_power';
  displayName: string;
  attackStyle: AttackStyle;
  effectKind: EffectKind;
  statBasis: 'elder_pct' | 'density' | 'area' | 'age75_pct' | 'temporary';
};
```

- `msg.includes('大魔法')`を削除。魔法か否かは`attackStyle==='magic'`または`skillId==='elder_magic'`等、**構造化された値**で決める。
- **現在の役割が前衛**で、攻撃が`melee`なら体当たり演出。元後衛でも昇格後は近接演出にする。
- `magic`・`ranged`・`support`は前衛位置に立っていても遠隔エフェクトでよい。**「昇格後は全員必ず体当たり」ではなく、現在役割×攻撃種別**の組み合わせで決定する。
- 通常攻撃は自治体の適性に応じて`melee`または`ranged`を明示的に定義する。Ver.0.4.2の暫定方針では、**前衛の通常攻撃＝melee／後衛の通常攻撃＝ranged**を基本とし、昇格後は現在役割に従う。固有必殺技はその技定義に従う。

### 6.2 長老の大魔法へのMAG反映

通常攻撃はATK参照、魔法系攻撃はMAG参照へ分ける（式は暫定）。

```text
通常攻撃ダメージ
  = round(16 × (ATK/100)^0.8 × (100/対象DEF)^0.6 × 乱数[0.95,1.05])

長老の大魔法ダメージ
  = round(16 × 1.9 × (MAG/100)^0.8 × (100/対象DEF)^0.6 × 乱数[0.95,1.05])

回復必殺技
  = round(26 × (MAG/100)) 〔既存挙動を暫定維持〕
```

- `MAG`が高い自治体の魔法威力が上がり、`ATK`を変更しても魔法の威力が変わらないこと。
- この変更は**ゲームバランスを変える仕様変更**なので、旧Ver.0.4.1と完全に同じ勝敗になる必要はない。一方で**Ver.0.4.2内部での同seed再現性**を守る。
- 既存のMAG計算式自体は本修正の対象外。バランス計測後に調整する。

### 6.3 KO位置の取得と遷移

- 単独KO・後衛昇格後のKOでは`effectivePos()`または補間済み描画座標から`koPosition`を保存。
- **同時KOでは、昇格判定前に両者のKO位置を先に記録**する。
- KOイベントは描画上の消滅を扱い、`hp=0`ユニットのキャラ本体は待機描画から除外する。
- 昇格イベントを表示する場合は生存後衛の移動が完了してから次の行動を描画する。昇格中にシミュレーション判定を進めても描画の到達位置を破綻させない。

## 7. ドラフトの再抽選とシード（F03）

### 7.1 操作名と責務を一致させる

| 操作 | 実行関数 | 残すもの | やり直すもの |
|---|---|---|---|
| **候補を再抽選** | `rerollPool()` | 敵2体、battleSeed、指名／選択済み自治体、編成希望 | **未選択の候補枠のみ** |
| **ドラフトを最初から** | `newGame()` | ゲーム設定（速度など） | 敵、候補、選択、編成、battleSeed |
| **同じシードで再戦** | `startBattle(existingSeed)` | 編成、敵、battleSeed、速度 | 戦闘状態・演出キューのみ |
| **新シードで再戦** | `startBattle(newSeed)` | 編成、敵、速度 | battleSeedと戦闘状態 |

### 7.2 再抽選の詳細ルール

- 再抽選は6枠のうち**選択済みの自治体は固定**し、残り枠を新候補に差し替える。
- 重複を禁止：候補内6体・敵チーム2体との重複なし。指名した自治体は選択済みであれば候補内に固定。
- プレイヤーの選択が2体なら、6枠のうちその2体を固定して残り4枠だけ更新する。ただし選択解除後は対象枠も次回再抽選に含める。
- **`battleSeed`と`draftRng`は別管理**。候補再抽選で戦闘用seedを変更しない。対戦の同seed再現テストを容易にする。
- もし未選択候補が十分に残っていなければ、抽選可能な範囲で更新し、処理停止しない。
- ラベルは「候補を再抽選（選択・相手は保持）」とし、別に「最初からやり直す」を設ける。

## 8. 表示の安全性、再生速度、DOM負荷（F08・F09・F11）

### 8.1 HTML文字エスケープ

```js
const HTML_ESCAPES = {
  '&': '&amp;', '<': '&lt;', '>': '&gt;',
  '"': '&quot;', "'": '&#39;'
};
function esc(s) {
  return String(s).replace(/[&<>"']/g, c => HTML_ESCAPES[c]);
}
```

- 自治体名は現状の公式名だけでなく、テスト入力の `A&B <C> "D" 'E'` に対して崩れず表示される。
- ユーザー入力は可能な限り`textContent`で表示し、HTML文字列を構築する場合のみ`esc()`を適用する。

### 8.2 再生速度の保持

- `playbackSpeed`を`startBattle()`で初期化しない。初期値0.85倍は**アプリ起動時に一度だけ**設定。
- 「同シード再戦」「新シード再戦」「ドラフトから新規対戦」の間、同一ページ内では選択速度を保持する。
- 再読み込み後の永続化は今回不要。テストで速度を変更しても、**戦闘結果は同じ**になる。

### 8.3 HUDの差分更新

- 初回はDOMノードを生成し、HP・役割・シールドなどの変化した表示のみ`textContent`やスタイル幅を更新する。
- 代替として**最大10 Hz**の定期更新を許容。ただし**KO・昇格・戦闘終了イベント時は即時更新**する。
- 役割変更やHP変化のないフレームでは`hud.innerHTML`へ代入しない。
- Canvasのキャラ位置・床・エフェクト描画は従来どおりFPS依存で実行してよいが、Canvas描画自体で戦闘ロジックを進めない。

## 9. UIの確認観点（スマホ優先）

1. 前後の奥行き：後衛は上・小さく、前衛は下・大きい。昇格時は後衛が手前へ移動。
2. 誰が攻撃したか：行動バナーに「**発動者 → 対象：技名**」を表示。必殺技名と統計根拠を必要な場面に限定。
3. KO：倒れた位置で約0.35〜0.6秒のKO・消滅エフェクトを表示。倒れたキャラが立ち続けたり、空所にKOだけ浮かない。
4. 最後の一撃：致死ダメージ数値とKOが必ず見え、決着演出後に結果へ。
5. 攻撃種別：近接は接近→接触→後退、魔法は光弾・軌跡、支援は味方方向のエフェクト。技名だけを変えてもモーションは変わらない。
6. 最低限の表示：4体の名前とHP、現在前衛／後衛、技の発動者・対象、経過／残り時間。攻撃ログを大きく積み重ねない。
7. 視認性：Android Chrome相当の390×844および一般的なPC表示で、重なり・画面外はみ出し・意図せぬスクロールがない。

## 11. 移行手順・実装完了の定義

### 11.1 推奨改修順

1. **状態モデル刷新**：`initialSlot`／`effectiveRole`／`isAlive`／`DisplayEvent`／座標スナップショット。二重生死フラグを排除。

3. **演出再生系の分離**：イベントID・順次キュー・致死ダメージの描画。
4. **終局遷移**：計算終了と画面遷移を分離し、最低1秒の決着余韻。
5. **攻撃種別とMAG**：技ID・近接／魔法分岐・魔力参照。
6. **シールドの有効期限と上限**：内部状態、AI条件、表示。
7. **ドラフト再抽選の責務分離**：敵と選択を保持し、候補のみ差し替え。
8. **低リスク修正**：HTMLエスケープ、速度保持、HUD差分更新。
9. **全テスト**：T01～T26とAndroid／PC手動確認、同seed再現性、複数シードのバランス計測。

### 11.2 完了条件（Definition of Done）

- **P0のT01～T10が全件合格**。決着攻撃が一度も描画されず画面遷移するケースがない。
- **F01～F11のすべてが実装済み**で、対応テストに合格している。
- 実データ（福岡県60市町村）と架空要素の説明が画面上で明確に分離されている。
